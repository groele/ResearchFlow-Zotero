**面向手稿流水线、期刊投稿、同行评审和私有元数据同步的本地优先 Chrome 工作区。**

**简体中文** · [English](README.md)

- 当前版本：**9.0.0**
- 浏览器要求：**Google Chrome 116 或更高版本**
- 运行方式：**Manifest V3、原生 JavaScript、无需构建**

**9.0 新增：**分享工作台支持 13 种卡片风格可视化选择、三档品牌大小，以及标准／高清／超清 PNG 导出。长图自动控制位图尺寸并明确提示；重置设计保留隐私选择，预览失败可直接重试。现有数据和设置继续兼容。详见 [发布说明](RELEASE_NOTES_v9.0.0.md)。

## 为什么使用 ResearchFlow

论文投稿过程往往分散在浏览器标签页、邮箱、Excel、笔记软件和多个出版商平台中。ResearchFlow 关注的是最容易遗漏、但会直接影响投稿管理的问题：

- 当前有哪些稿件仍在推进？
- 每篇稿件投到了哪个期刊、使用哪个投稿入口？
- 当前只是完成投稿，还是已经真正进入审稿？
- 第一轮审稿意见是什么时候返回的？
- 返修截止日期是哪一天？
- 每一条审稿意见是否已经回复？
- 从投稿到接收实际用了多少天？
- 哪个项目、手稿和投稿记录属于同一条工作流？

ResearchFlow 坚持 **本地优先**：

- 无需注册云端账号即可使用；
- 默认数据库保存在 Chrome 本地扩展存储中；
- WebDAV 和 GitHub 同步均由用户主动选择；
- 投稿网站捕获结果必须经过人工核对后才会创建记录。

## 核心工作流

```text
项目
  └─ 手稿
       ├─ 写作与图件准备
       ├─ 投稿记录
       │    ├─ 目标期刊与投稿入口
       │    ├─ 稿件编号与关键日期
       │    ├─ 投稿合规清单
       │    ├─ 审稿与返修事件
       │    └─ 审稿意见回复矩阵
       └─ 接收、上线与发表里程碑
```

当前主程序包含四个工作区：

| 板块 | 用途 |
| --- | --- |
| **仪表盘总览** | 汇总指标、稿件流水线、关键事件时间轴、等待时长、第一作者和待处理里程碑。 |
| **手稿看板** | 按想法、写作、投稿审稿、接收发表等阶段管理手稿。 |
| **投稿与审稿** | 管理投稿记录、期刊入口、日期、合规清单、审稿事件和回复矩阵。 |
| **多云设置** | 语言、投稿网站识别、本地/云端路由、连接测试、JSON 导出导入和恢复。 |

点击 Chrome 工具栏中的扩展图标会直接打开完整主程序。当前版本不注册弹出窗口，也不使用侧边栏。

## 功能总览

### 仪表盘总览

- 显示投稿总数、活跃审稿数量、已接收/已发表数量。
- 点击汇总卡片可以筛选稿件流水线。
- 支持紧凑和展开两种时间线视图。
- 在投稿日期来源后显示第一作者。
- 在日期完整时计算：
  - 实验完成到投稿；
  - 投稿到今天；
  - 第一轮审稿意见到今天；
  - 投稿到接收；
  - 接收到在线发表。
- 汇总即将到期或最近发生的时间线事件。

仪表盘可能显示 `R1 之后`、`在线` 等由时间线推断的阶段。这类信息不是投稿编辑器中的原始状态字段，详见[状态模型](#状态模型)。

### 手稿看板

- 新建和编辑手稿。
- 跟踪从想法到发表的完整阶段。
- 将稿件归入：
  - 想法与提纲；
  - 写作与图件；
  - 投稿与审稿；
  - 已接收与已发表。
- 修改手稿生命周期状态时，同步更新关联的活跃投稿记录。
- 保存标题、目标期刊、作者信息、摘要草稿和更新时间。

### 投稿记录器

- 创建新投稿，并关联已有手稿。
- 从经过人工核对的投稿网站捕获结果创建相互关联的项目、手稿和投稿记录。
- 记录：
  - 目标期刊；
  - 投稿入口；
  - 外部稿件编号；
  - 第一作者和作者列表；
  - 投稿状态；
  - 投稿日期；
  - 第一决定日期；
  - 接收或发表日期；
  - 返修截止日期；
  - 摘要与关键词；
  - 流程备注和时间线事件。
- 编辑投稿信息时自动保存，常规填写不需要单独点击保存按钮。
- 捕获结果与现有投稿匹配时，打开已有记录，避免重复创建。
- 支持标记拒稿并转投其他期刊，同时保留上一轮投稿历史。

### 合规检查与同行评审

- 维护投稿前合规检查项。
- 跟踪多轮审稿和返修事件。
- 保存审稿意见及回复进度。
- 将审稿回复内容导出为可复用表格。
- 将所有流程上下文保留在当前投稿记录中，不再分散到独立模块。

### 数据可靠性

- 使用本地优先数据库和 schema 规范化。
- 后台串行处理数据库写入，降低多个自动保存操作相互覆盖的风险。
- 同步时按实体标识和更新时间合并集合。
- 使用删除墓碑，防止旧的远程快照把已删除条目重新恢复。
- 从导出文件和远程数据库中移除同步凭据。
- 导入前检查 JSON 大小和数据结构。
- 在当前设备保留一个“导入前恢复点”。

## 状态模型

ResearchFlow 中存在三个相互关联、但含义不同的状态概念。理解它们可以避免把跨板块差异误认为数据损坏。

### 1. 手稿状态

手稿看板使用的全局生命周期：

| 内部值 | 含义 |
| --- | --- |
| `idea` | 初始研究或论文想法 |
| `outline` | 提纲与规划 |
| `data_collection` | 数据收集 |
| `figure_preparation` | 图件准备 |
| `drafting` | 手稿撰写 |
| `internal_review` | 投稿前内部审阅 |
| `submitted` | 已完成投稿 |
| `under_review` | 编辑处理或同行评审中 |
| `revision` | 返修中 |
| `accepted` | 已被期刊接收 |
| `published` | 已发表 |

### 2. 投稿状态

某一次具体投稿尝试的状态：

| 内部值 | 中文标签 | 含义 |
| --- | --- | --- |
| `submitted` | 已投稿 | 已完成提交，但不代表已经确认进入外审 |
| `under_review` | 审稿中 | 编辑处理或同行评审中 |
| `revision` | 返修中 | 已要求修改或正在准备返修 |
| `accepted` | 已接收 | 当前投稿已经被期刊接收 |
| `published` | 已发表 | 已接收论文已经发表 |
| `rejected` | 已拒稿 | 当前投稿尝试被拒绝 |

旧数据库中的 `accept`、`in_review`、`online` 等别名会在加载时规范化为当前标准值。

### 3. 时间线推断阶段

仪表盘还会根据关键日期生成用于展示的流程阶段：

- 存在投稿日期、尚无更晚事件时显示“审稿中”；
- 存在第一轮审稿事件时显示“R1 之后”；
- 存在接收事件时显示“已接收”；
- 存在上线事件时显示“在线”。

这些标签用于描述时间线位置，不能代替投稿记录中可编辑的真实状态。遇到不同板块标签不一致时，应先确认页面展示的是手稿状态、投稿状态还是时间线阶段。

## 投稿网站智能识别

ResearchFlow 可以识别主流期刊投稿系统，并直接在投稿网页内显示紧凑的快捷录入卡片。

### 当前支持的平台

| 平台 | 识别域名 |
| --- | --- |
| ScholarOne Manuscripts | `*.manuscriptcentral.com` |
| Editorial Manager | `*.editorialmanager.com` |
| eJournalPress | `*.ejournalpress.com` |
| ACS Paragon Plus | `publish.acs.org` |
| Wiley Submission | `submission.wiley.com` |
| Springer Nature Submissions | 受支持的 Nature 投稿域名 |
| AIP Peer X-Press | `*.peerx-press.org` |
| MDPI SuSy | `susy.mdpi.com` |
| Frontiers Review | `review.frontiersin.org` |
| APS Authors | `authors.aps.org` |
| Science Journals Submission | `submission.science.org` |

识别器会综合域名、页面标题、元数据、表单字段标签和可见流程文本进行判断。出版商可能随时调整页面结构，因此捕获结果必须由用户核对。

### 捕获流程

1. 访问受支持的期刊投稿网站。
2. 页面加载完成后，ResearchFlow 判断投稿平台。
3. 当前网页内出现紧凑的快捷录入卡片。
4. 点击 **一键捕获信息**。
5. ResearchFlow 直接打开主程序，并显示只占部分页面宽度的核对表单。
6. 人工检查和修改识别到的字段。
7. 确认创建。
8. 系统创建相互关联的项目、手稿和投稿记录；如果发现匹配记录，则直接打开原记录。

在用户确认核对表单以前，不会正式创建记录。

### 可能捕获的字段

- 期刊名称和投稿入口；
- 稿件标题；
- 外部稿件编号或参考编号；
- 流程状态；
- 投稿日期；
- 返修截止日期；
- 第一作者；
- 作者列表；
- 摘要；
- 关键词。

核对页面会显示识别置信度和捕获字段数量。高置信度只代表页面信号较充分，不代表所有字段一定正确。

### 明确不采集的字段

投稿网站采集器会跳过：

- 密码输入框；
- 邮箱输入框；
- 文件选择框和上传的手稿文件；
- 隐藏表单字段。

### 功能开关

“多云设置”中提供两个独立开关：

- **自动识别投稿网站**：控制是否在受支持网站内显示快捷录入提示。
- **自动捕获投稿信息**：控制是否采集详细稿件字段供人工核对。关闭后仅携带期刊、入口和日期等基础上下文进入手动录入。

用户可以在单个网站上忽略提示，并可在设置中恢复所有已忽略网站。

## Google Scholar 与镜像捕获

ResearchFlow 可以从 Google Scholar 官方结果页及结构兼容的镜像网站捕获论文元数据，不依赖容易失效的固定镜像域名列表。

1. 打开 Scholar 搜索结果页面并点击 ResearchFlow 工具栏图标。
2. 插件只在本次点击后临时检查当前标签页的 Scholar 结果结构。
3. 存在多条结果时，在紧凑选择器中选择目标论文。
4. 核对标题、期刊、作者、DOI、文章链接、摘要、来源域名和识别置信度。
5. 确认表单后创建或更新手稿。

识别器要求页面同时存在有效结果容器以及 Scholar 元数据或搜索结构。Scholar 首页、空结果页以及仅偶然包含相似标签的普通网页不会生成空手稿。

Scholar 捕获论文默认状态为“已发表”，但用户可以修改。重复检测依次比较 DOI、规范化文章链接和规范化题目。作者信息会拆分成列表，并明确保存第一作者；来源记录会保留人工核对标记。任何内容在用户确认前都不会写入数据库。

页面检查仅在用户点击图标后通过临时 `activeTab` 权限执行，不会持续读取任意网站的浏览历史。

## 安装与更新

ResearchFlow 当前以“加载已解压扩展程序”的方式安装。

### 从本地仓库安装

1. 下载或克隆仓库：

   ```powershell
   git clone https://github.com/groele/ResearchFlow-Extension.git
   cd ResearchFlow-Extension
   ```

2. 在 Google Chrome 打开 `chrome://extensions`。
3. 启用右上角的 **开发者模式**。
4. 点击 **加载已解压的扩展程序**。
5. 选择直接包含 `manifest.json` 的仓库目录。
6. 将 **ResearchFlow Companion** 固定到 Chrome 工具栏。
7. 点击扩展图标，打开完整主程序。

### 更新已加载的扩展

1. 重要数据库建议先导出 JSON 备份。
2. 拉取或替换仓库文件。
3. 打开 `chrome://extensions`。
4. 点击 ResearchFlow 卡片上的 **重新加载**。
5. 重新打开主程序并核对左侧显示的版本号。

重新加载扩展文件通常不会删除 `chrome.storage.local` 中的数据，但大版本升级前仍建议保留独立备份。

### 特别注意加载目录

Chrome 实际运行的是执行“加载已解压的扩展程序”时选中的目录。修改另一份同名仓库不会自动影响已经安装的插件。请在 `chrome://extensions` 中核对 ResearchFlow 的实际加载路径。

## 快速开始

### 手动新建手稿

1. 打开 **手稿看板**。
2. 点击 **新建手稿**。
3. 填写标题和已有元数据。
4. 选择当前手稿阶段。
5. 保存手稿。

### 新建投稿记录

1. 打开 **投稿与审稿**。
2. 点击 **新建投稿记录**。
3. 选择已有手稿，或按流程创建关联记录。
4. 填写期刊、投稿入口、第一作者和已有日期。
5. 确认创建。
6. 在投稿工作区继续填写；支持的编辑字段会自动保存。

### 记录一轮审稿

1. 打开对应投稿。
2. 添加第一决定或审稿意见事件。
3. 如需返修，填写返修截止日期。
4. 录入审稿意见和回复进度。
5. 添加返修提交事件。
6. 收到期刊决定后更新投稿状态。

### 标记接收与发表

- 期刊正式接收当前投稿时，使用 `已接收`。
- 论文正式发表后，使用 `已发表`。
- 补充接收日期和上线日期后，仪表盘才能计算完整周期。

## 数据存储与同步

### 仅本地模式

默认使用本地模式：

- 不需要任何同步账号；
- 数据库保存在 Chrome 当前配置文件的扩展本地存储中；
- 因为没有远程目标，“强制同步”按钮会保持禁用。

删除 Chrome 配置文件、清理扩展数据或浏览器配置损坏可能导致本地数据库丢失。重要数据应定期导出 JSON。

### WebDAV 同步

ResearchFlow 会读写：

```text
<WebDAV 基础 URL>/researchflow_db.json
```

必填配置：

- 以 `http://` 或 `https://` 开头的基础 URL；
- 用户名；
- 应用密码。

示例：

```text
https://dav.example.com/researchflow
```

首次配置后，请点击 **测试 WebDAV 连接**，用于检查凭据并授予该 WebDAV 来源所需的可选主机权限。不能填写本地磁盘路径、缺少协议的域名或 FTP 地址。

### GitHub 私有仓库同步

GitHub 同步会把 `researchflow_db.json` 保存到指定分支。

必填配置：

- Personal Access Token；
- `所有者/仓库名` 格式的仓库；
- 分支名称，通常为 `main`。

建议使用私有仓库，并将 Token 权限限制到目标仓库的 Contents 读写。ResearchFlow 使用 GitHub Contents API，并在更新远程文件时保留文件 SHA。

### 同步逻辑

- 本地修改会先保存，再调度云端同步。
- 远程文件不存在时，上传当前本地数据库。
- 本地与远程实体集合按标识和更新时间合并。
- 删除墓碑会先合并，再过滤已经删除的实体。
- 当前设备的本地设置保持优先。
- 配置缺失或无效时，同步会被跳过并显示明确错误。
- 云同步不是实时协同编辑；不建议多个设备同时修改同一条记录。

### 凭据边界

GitHub Token 和 WebDAV 凭据保存在独立的设备本地存储项中，并从以下内容中排除：

- JSON 导出文件；
- WebDAV 远程数据库；
- GitHub 远程数据库。

浏览器扩展存储并不等同于操作系统专用密码保险库。请使用最小权限凭据；设备丢失或凭据疑似泄漏时应立即撤销。

## 备份、导入与恢复

### 导出数据库

进入 **多云设置 → 数据库备份与导入 → 导出数据库**。

导出的 JSON 是经过清理的可移植数据库，不包含同步密码、Token 和临时 GitHub SHA。

### 导入数据库

1. 建议先导出当前数据库。
2. 点击 **导入 JSON**。
3. 选择不超过 25 MB 的 ResearchFlow 数据库备份。
4. 确认导入。
5. 核对仪表盘、手稿数量和投稿数量。

系统会先检查文件大小和数据库结构，再替换活动数据库。受支持的旧 schema 会迁移到当前结构。

### 恢复导入前备份

有效的导入文件替换当前数据库前，ResearchFlow 会在本设备保留一个滚动恢复点。点击 **恢复导入前备份** 可以返回该状态。

需要注意：

- 恢复点只保存在当前设备；
- 下一次有效导入会替换上一份恢复点；
- 它不能代替保存在其他位置的独立 JSON 备份。

## 隐私与权限

### 数据处理原则

- 默认只在本地保存研究数据。
- 投稿网站捕获仅在 manifest 声明的受支持域名中运行。
- 捕获信息会先展示给用户核对，确认后才创建记录。
- 不采集密码、邮箱字段和上传文件。
- WebDAV 和 GitHub 同步均为可选。
- 同步凭据只保存在设备本地，不进入可移植数据库。
- 当前版本不包含泛化 AI 助手，也不会把手稿文本发送给 AI 服务商。

### 扩展权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存本地数据库、设置、凭据和导入前恢复点。 |
| `tabs` | 投稿捕获后打开或聚焦 ResearchFlow 主程序。 |
| `activeTab` | 用户点击工具栏图标后，仅临时检查当前标签页。 |
| `scripting` | 将插件自带的 Scholar 识别器注入本次临时授权的标签页。 |
| `unlimitedStorage` | 允许本地研究数据库超过扩展默认的小容量配额。 |
| 受支持投稿域名权限 | 识别投稿网站并显示快捷录入卡片。 |
| `https://api.github.com/*` | 用户启用 GitHub 数据库同步时访问 Contents API。 |
| 可选 `http://*/*`、`https://*/*` | 仅为用户配置的 WebDAV 来源请求访问权限。 |

如果所在机构对浏览器扩展处理科研数据有专门规定，请在安装前检查 `manifest.json` 和相关政策。

## 已移除模块与迁移说明

以下早期实验模块不再属于 v7 的活动产品：

- 领域与项目树主面板；
- 研究记录主面板；
- Evidence Locker；
- 泛化 AI 助手；
- 弹出面板；
- 浏览器侧边栏。

历史 Evidence Locker 数据 **不会为了兼容而保留**。数据库升级到 schema 7 时，会清除已退役的 Evidence Locker 字段、AI 凭据、证据文件路由和旧文件同步设置。

当前数据库仍规范化以下活动集合：

- 项目；
- 为数据库结构兼容保留的研究记录集合；
- 手稿；
- 投稿；
- 任务；
- 删除墓碑。

升级到 schema 7 后，不要再让旧版本客户端写入同一个远程数据库。旧客户端无法理解删除墓碑协议，可能破坏删除同步结果。

## 常见问题排查

### 点击扩展图标没有打开主程序

1. 打开 `chrome://extensions`。
2. 确认 ResearchFlow 已启用。
3. 点击“错误”查看 Service Worker 报错。
4. 重新加载扩展。
5. 核对 Chrome 加载的是当前包含 `manifest.json` 的目录。

### 修改代码后界面没有变化

Chrome 可能加载了另一份同名目录。请在 `chrome://extensions` 核对实际加载路径，修改文件后重新加载扩展。

### `Invalid WebDAV URL`

必须填写完整的 HTTP 或 HTTPS 基础 URL：

```text
https://dav.example.com/researchflow
```

以下写法无效：

```text
D:\researchflow
dav.example.com/researchflow
ftp://dav.example.com/researchflow
```

填写正确后先点击 **测试 WebDAV 连接**，授予来源权限，再执行强制同步。

### GitHub 连接失败

- 仓库应填写为 `所有者/仓库名`，不能填写网页 URL。
- 确认所填分支已经存在。
- 确认 Token 对目标仓库 Contents 具有读写权限。
- 建议使用私有仓库。
- 可能泄漏的 Token 应立即撤销并重新创建。

### 投稿网站没有弹出识别提示

- 确认网站属于当前支持的平台。
- 在“多云设置”中启用“自动识别投稿网站”。
- 如果以前忽略过该网站，点击恢复已忽略的网站。
- 重新加载插件后刷新投稿网页。
- 出版商页面结构可能已经变化；此时可先手动录入投稿，并报告受影响的域名或 URL 模式，但不要提交密码、Token、邮箱或保密稿件内容。

### 自动捕获的信息不完整或不正确

识别属于启发式判断。必须重点核对：

- 期刊名称；
- 稿件编号；
- 流程状态；
- 第一作者；
- 日期。

确认创建以前，可直接在核对表单中修正。置信度只是辅助指标，不是正确性证明。

### 不同板块显示的状态不一样

先确认页面显示的是：

- 手稿状态；
- 某一次投稿的状态；
- 或仪表盘根据日期推断的时间线阶段。

详见[状态模型](#状态模型)。如果两个页面明确展示同一种状态但仍不一致，建议先导出数据库，再记录稿件标题、两个板块名称和复现步骤。

### 强制同步按钮不可用

仅本地模式下这是正常行为。完整配置 WebDAV 或 GitHub 后，才能执行手动同步。

### 导入后数据异常

应立即使用 **恢复导入前备份**，然后检查导入的 JSON。不要连续进行多次导入，因为系统只保留一个滚动恢复点。

## 当前限制

- 当前只正式支持 Chrome/Chromium，不支持 Firefox 和 Safari。
- 当前以加载已解压扩展程序的方式分发。
- 投稿识别依赖出版商页面结构和文字，网站改版后可能暂时失效。
- 自动捕获属于启发式识别，必须人工核对。
- 云同步不是多人实时协作系统。
- 应避免多台设备同时修改同一条记录。
- 凭据保存在扩展本地存储中，不是操作系统级密码保险库。
- 仪表盘时间线阶段与可编辑状态属于相关但不同的概念。
- 当前项目没有构建系统和静态类型检查器。
